# Plan 007：站点结构采集与 API MCP Demo

状态：PLANNED。日期：2026-09-10。本文仅为执行计划，尚未开始实现或真实站点验证。

## 目标

以 RDMS「应用详情 → 部署实例列表」为完整验收流程，交付两项可展示的能力：

1. 生成的 Skill 包含页面入口、模块、控件和导航关系，使用 Playwright MCP 的模型可据此规划操作，减少逐个试探。
2. 从页面脚本和实际网络请求采集业务 API，生成具名 MCP 工具；调用时复用浏览器会话，实际请求原接口，支持改变业务参数并返回结构化结果。

Demo 简化生产工程和特殊兼容处理，不简化采集、生成、调用和结果核验。工具注册成功、复用手写 RDMS 工具、用 DOM 读取冒充接口调用，均不算完成。

## 当前证据与执行前检查

- 扩展已采集交互元素和表格，并探索部分链接与一级 SPA 导航。
- `src/generator/skillPackage.ts` 会将 Skill 正文重建为固定 action 索引，结构说明无法保留。
- 生成器尚无脚本和网络证据输入，提示词明确禁止 API calls。
- 具名 MCP 注册、文件变化通知、参数校验、本地服务和 Chrome Bridge 可以复用。
- 现有 `rdms_list_deployment_instances` 读取 DOM，要求当前标签页匹配部署路由，不是 API 工具。
- RDMS 的接口地址、方法、参数、响应和认证方式尚未在本计划中验证，不得根据页面路由猜测。
- 工作区已有大量修改和未跟踪文件。执行前重新检查 `git status --short` 及相关 diff，在当前实现上增量修改，不回退或整理任务无关内容。

## 范围

必须完成：目标流程的结构与导航采集；内联和实际加载的同源业务脚本采集；fetch、XHR 及 axios 发出的真实请求/响应采集；参数化 API action 生成；浏览器会话执行；真实站点结果对照。

不做：全站覆盖承诺、所有打包格式的完整静态分析、任意动态签名破解、自动执行写接口、生产级审计/RBAC/队列/重试平台、另建 MCP 服务及无关运行时重构。

只读查询不能仅按 GET 判断：观察到的 POST 查询也应支持，但必须以目标页面的实际业务行为确认语义。创建、部署、删除等写请求不参与自动重放。

## 产物与最小数据约定

沿用 `skills/<domain>/`，增加结构说明和 API reference，不另建知识库平台。

| 产物 | 最少内容 |
| --- | --- |
| `SKILL.md` | 覆盖范围、页面地图入口、任务与 API 工具索引、Playwright 操作步骤 |
| `site-map.json`、`site-map.md` | 页面 URL/标题、模块、控件名称及 selector、导航来源/目标、前置状态、已观察/未验证标记 |
| `references/<api-action>.md` | 工具用途、输入输出 schema、声明式请求定义、采集来源、验证状态 |
| Demo 验收记录 | 覆盖范围、接口来源、调用一致性、参数变化结果、未覆盖项 |

API action 使用显式 API 执行类型，与 DOM read/write 区分。定义包含已观察的 method、origin、路径、query/body 参数映射及必要的响应提取规则，不包含模型生成的任意 JavaScript。

业务 ID、分页和搜索条件可以成为输入；Cookie、token 和认证 header 值不得写入 Skill、模型输入或持久化测试证据，执行时从会话取得。响应原文只作临时验证，持久化优先保存字段结构和脱敏摘要。

不假定页面路由中的 `appCode/sysCode/env/appName` 都是接口参数，必须以实际请求为准。输出保留真实业务字段、类型和列表含义，不编造字段。

## 执行步骤

### 1. 确认真实流程与采集方式

1. 检查当前实现及测试浏览器配置，确认 RDMS 登录会话可用。
2. 在进入目标页面之前开启监听，再进入应用详情和部署实例模块；记录结构、脚本和只读查询请求。切换一个可用应用或环境，取得第二组对照请求。
3. 对应脚本中的调用位置与网络证据，确认可变业务字段、响应结构和认证来源。
4. 选择一套能取得请求和响应体的浏览器采集机制，优先评估扩展可用的 Chrome 调试协议能力。不同时维护多套监听实现；如需调整扩展权限，同步重载说明。

验收：至少一个业务接口的完整证据，以及目标模块的入口、结构和导航路径。确认是否有动态签名、跨域或页面初始化依赖。

缺少登录态、页面权限或第二组有效参数时报告具体缺口；可继续本地实现，但不能标记真实验收通过。真实页面操作限定为读取流程，外部副作用按用户约束另行确认。

### 2. 保存结构并生成页面地图

1. 扩展快照以保留模块/控件层级、稳定 selector、链接目标及必要页面状态，不只输出扁平元素列表。
2. 保存从哪个入口到达哪个页面的关系，将目标流程需要的二级菜单、Tab 和展开动作纳入采集，只走已确认的导航和读取动作。
3. 同一路由不同 Tab/模块按状态记录，不能仅因 URL 相同而去重丢失。
4. 修改 Skill 合并逻辑，保留结构说明、按页面和状态增量合并、保留旧 action。未探索入口明确标记，不编造关系。
5. Skill 指导模型先读地图再选 API 或 Playwright；不假定 Playwright MCP 会自行加载 Skill。

验收：只读生成产物即可指出应用详情及实例模块的到达步骤、关键控件和前置条件；再次生成后这些信息仍在。

### 3. 从脚本与网络证据生成 API action

1. 采集内联及实际加载的业务脚本，包括探索中懒加载的脚本；提取接口线索，不仅匹配字面量 `fetch('/api/...')`。
2. 网络监听还原真实 method、URL、query/body、必要 header 名称及响应。筛除静态资源、遥测，按 endpoint、method 和请求结构归并，关联触发页面/控件。
3. 脚本发现但未观察到请求的接口保留为候选，不直接发布。脚本无法定位时明确标记，不能虚构来源。
4. 根据对照请求和页面语义识别可变字段，生成输入 schema 和参数映射，不能把单次抓取的业务 ID 永久写死。
5. 模型负责命名、用途及参数语义；方法、地址、字段和映射必须有证据并接受本地校验。
6. 根据响应生成输出定义，执行一次已确认的只读接口验证后才标记为可发布。

验收：至少一个 API action 从采集数据自动生成，有真实脚本/请求来源；改变业务参数后能构造正确请求。不手工补写 RDMS endpoint 代替生成能力。

### 4. 接通 API MCP 调用

1. 在现有 action 解析、注册、服务和桥接中增加 API 分支，沿用 MCP 发现及调用入口。
2. 在浏览器会话执行声明式请求，复用实际认证方式。优先支持当前同源登录标签页，不要求停在实例列表精确路由；确实存在页面初始化依赖时如实记录。
3. 对 HTTP 错误、非 JSON、超时和输出超限返回明确错误，不悄悄退回 DOM 读取。
4. 新工具使用独立稳定名称，例如 `rdms_api_list_deployment_instances`，保留旧 DOM 工具并在描述中区分，避免名称冲突和验收误用。
5. 扩展至少显示采集页面、发现接口及可用工具；失败不能显示为完成。更新 README 的生成、重载、调用和演示步骤。

验收：新工具出现在 `tools/list`；`tools/call` 发起真实业务请求并返回接口数据。在另一同源页面调用，验证是否摆脱列表页依赖。

### 5. 完成端到端展示与记录

1. 本地示例站覆盖多级导航、同 URL Tab、外部脚本、异步请求、参数化列表和会话校验，验证采集到调用的完整链路，不代替 RDMS 验收。
2. 用生成 Skill 指导使用 Playwright MCP 的模型完成目标导航，记录路径及额外探索次数；关键入口不依赖执行者口头提示。
3. 对 RDMS 同组参数比较页面原始 API 与 MCP 返回的列表数量、稳定业务字段，动态字段单独注明，采样尽量相邻。
4. 换第二组有效业务参数再次调用并与对应原接口结果核对，证明不是固定样例。不存在分页等能力时不虚构演示。
5. 记录脱敏来源、已验证效果及实际限制；失败如实保留，不以 mock 成功替代真实结果。

## 改动范围与验证方式

| 范围 | 预计文件 | 必要验证 |
| --- | --- | --- |
| 采集和进度 | `extension/content.js`、`background.js`、`popup.js/html`，按需调整 manifest | 结构关系、请求/响应捕获、敏感会话信息不落盘 |
| 生成和保存 | `src/generator/`、`src/server.ts`，少量新增合约/采集文件 | 增量保留、来源约束、参数映射、候选不误发布 |
| 执行 | action 解析/注册、`src/bridge.ts`、扩展，按需调整 `src/mcp.ts` | 原 API 请求、换参数、错误反馈、旧 action 兼容 |
| 演示与文档 | fixture、相关测试、README、RDMS 验收文档 | 完整本地集成、真实站点对照 |

运行相关测试文件及 `npm run typecheck`，不为形式运行全量测试。优先使用现有 Playwright、扩展 API 和 Node 能力；新增依赖前确认现有依赖无法完成，再按用户约束确认。模型生成验证单独标明是否真的调用了模型，不把 mock 当作生成效果证明。

## 风险与回滚

- 动态签名、认证或跨域可能阻碍重放。先依据步骤 1 的证据选择最小实现；无法完成时报告原因，不擅自改成 DOM 读取。
- 调试协议可能与 DevTools/其他调试连接冲突。开始时给出可操作错误，结束后解除本次连接，不中断用户其他浏览器会话。
- 页面及接口数据可能变化；结构按状态记录，对比稳定字段，并记录采集/验证时间。
- 按步骤分批验证，新生成产物先放独立 Demo 工作目录，MCP 也使用该目录验证，不批量覆盖现有 `skills/`。通过验收后按约定目录交付。
- 回滚只撤销本任务引入的 API 分支、采集权限和新增产物，保留旧 DOM action 与用户已有修改，禁止整库 reset 或清理未跟踪文件。
